## Blueprint resources

- `PORT` is supplied by Render. Other application settings are defined in the Blueprint.

## Create the deployment

1. Commit and push the application and Blueprint to the GitHub branch you will connect.
2. In Render, choose **New > Blueprint**, connect the repository, and set **Blueprint Path** to `06-lab-complete/render.yaml`.
3. Review the proposed resources and verify that both plans are **Free** before approving the Blueprint.
4. Wait for the web service and Key Value instance to become available. Copy the service's `onrender.com` URL here and retrieve `AGENT_API_KEY` from the Render service's environment settings.
5. From `06-lab-complete/`, run `python check_production_ready.py --public-url https://<service>.onrender.com`.

## Smoke tests

Replace the URL with the deployed service URL:

```bash
curl --fail https://<service>.onrender.com/health
curl --fail https://<service>.onrender.com/ready
```

In PowerShell, set the API key locally from the Render dashboard without adding it to source control:

```powershell
$env:AGENT_API_KEY = Read-Host "Render AGENT_API_KEY"
curl.exe --fail -X POST "https://<service>.onrender.com/ask" `
  -H "X-API-Key: $env:AGENT_API_KEY" `
  -H "Content-Type: application/json" `
  -d '{"question":"Render deployment smoke test"}'
```

Expected results: `/health` and `/ready` return HTTP 200, and the authenticated `/ask` request returns HTTP 200.

## Free-plan limitations

Render Free web services spin down after 15 minutes without traffic and can take about a minute to start again. Free Key Value has 25 MB of memory and does not persist data across restarts, so rate-limit and cost-guard state can be lost. Render also applies included bandwidth and build-pipeline quotas; check the workspace billing page and spend limits before deployment. These plans are for a lab/demo, not production workloads.
